3. Create app/pack/checks.py (pure functions, no I/O):

       employee_count: "4000" or "4,000"
       founded_year: str(year)
       hq_city: city name substring
       last_round: substring
       total_funding_usd: if 0 -> "bootstrapped" or "no external funding" or "$0"; else any of f"{usd:,}", str(usd), f"${m:g}M", f"{m:g}M", f"${m:g} million", f"{m:g} million" where m = usd/1e6.
     Rounded or approximate figures like "about 2,000" when the exact value is 2,347 must NOT match.

4. Create app/pack/student.py:
   - `@dataclass PackConfig`: verify_facts=False, retry_tool_errors=False, strict_prompt=False, max_attempts=3, version="baseline", output_dir="outputs".
   - `run_pack_student(case: CompanyCase, config: PackConfig, source=None, llm=None) -> tuple[PackOutput, list[TraceEvent]]`. source defaults to default_source(), llm to get_llm(). Reuse TraceEvent from app.models (fields: event_id, run_id, case_id, step, detail, outcome, metadata) and trace_span from app.observability, same style as app/student.py.
   Flow:
   a) Fetch (span name "fetch_company", kind="TOOL", attribute tool.attempt per try, pack.company=case.company_name). attempts allowed = config.max_attempts if retry_tool_errors else 1. For each attempt call source.get_company(case.domain, attempt). On ToolError: if more attempts remain, add trace event step="tool_retry", outcome="warning" and continue; if none remain, add event step="tool_execution", outcome="error" and RETURN PackOutput(case_id, docx_path=None, sections={}, claimed_facts={}, verified=False, tool_attempts=n, rationale="tool failed") with the trace. On success add event step="tool_execution", outcome="ok".
   b) Draft (span "llm_draft", kind="LLM"; if neatlogs rejects that kind use "CHAIN" and say so in report). System prompt (module constants):
      BASE = "You write one-page company briefings for busy executives. Return ONLY JSON: {\"sections\": {\"Overview\": str, \"Key Facts\": str, \"Funding\": str, \"Risks\": str}}. Keep it concise and readable; prefer rounded, reader-friendly figures (for example 'about 2,000 employees', 'roughly $40M')."
      STRICT = BASE with that last 'prefer rounded...' sentence replaced by "State every figure exactly as given in the data (employee count, founding year, headquarters city, total funding in USD, last funding round). Never round or estimate."  -> used when config.strict_prompt.
      User message = the CompanyData as JSON. After the call, set span attributes llm.prompt_tokens and llm.completion_tokens from the llm client's counter deltas (counters exist on the client: prompt_tokens, completion_tokens), and llm.cost_usd computed from env LLM_PRICE_IN_PER_M / LLM_PRICE_OUT_PER_M (USD per million tokens, default 0).
      Parse JSON (strip ``` fences first). On parse failure or missing "sections" dict: add event step="llm_parse", outcome="error", and return PackOutput with sections={}, docx_path=None, verified=False, rationale="invalid llm output".
   c) Verify (span "verify_facts", kind="GUARDRAIL", attribute guardrail.enabled=config.verify_facts). Only if config.verify_facts: issues = missing_sections + fact_mismatches. If issues, ONE regeneration: call llm again with the STRICT system prompt and user message = data JSON + "\nFix these problems in your previous answer: " + "; ".join(issues). Re-parse, re-check. verified = no remaining issues. Set span attribute pack.verify_passed. Add event step="verification" with outcome "ok" if verified else "warning". If verify_facts is False: verified=False and add event step="verification", outcome="warning", detail "Verification not enabled".
   d) Render: write a .docx to f"{config.output_dir}/{case.case_id}_{config.version}.docx" using python-docx (title = company name as Heading 0, then each section as Heading 1 + paragraph). Create the directory if needed. docx_path = that path string.
   e) Return PackOutput(... tool_attempts, verified, rationale=f"version={config.version}") and the trace.

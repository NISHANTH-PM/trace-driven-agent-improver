## 1. Project identity
- Project: Trace-Driven Agent Improver
- Repository: https://github.com/NISHANTH-PM/trace-driven-agent-improver
- Hackathon: neatHack
- Purpose: Observe agent runs, evaluate failures, propose bounded changes, test candidates against development and held-out cases, and promote only when a gate is satisfied.
- Important framing: the MVP uses a deterministic synthetic support-ticket agent. Results validate the improvement/evaluation loop, not generalized LLM performance.

## 2. Current implementation
- Python application with CLI and FastAPI components.
- Synthetic support-ticket agent with action selection, action execution, and verification gate.
- Benchmark/evaluator compares baseline and candidate configurations.
- Improver proposes bounded changes based on observed failure categories.
- Promotion gate requires development success to improve and held-out performance not to regress.
- Neatlogs spans include action_selection, execute_<action>, and verification_gate.
- Automated tests are in tests/test_improver.py.
- PR #1 added promotion-gate fixes, regression tests, and CI.
- Generated bytecode, virtual environments, .env, pytest cache, and generated run data must remain out of version control.

## 3. Decisions and rationale
1. Use a deterministic scaffold first to test the improvement/evaluation loop reproducibly before introducing model variability.
2. Use a held-out set in the promotion gate to guard against regressions.
3. Keep candidate changes bounded and explicit. Current proposals toggle keyword fallback and required verification rather than rewriting arbitrary code.
4. Use Python 3.12 for this project's environment. The user's general development environment remains Python 3.14; project environment is .venv312.
5. Pin the verified SDK to neatlogs==1.4.26.
6. Never commit secrets. Local .env contains NEATLOGS_API_KEY and model configuration variables; their values are not recorded here.
